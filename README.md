# Inventory API

Складское приложение с веб-панелью и мобильным клиентом Expo для Android.
Сервер использует FastAPI и SQLAlchemy. База данных — SQLite или PostgreSQL,
миграции — Alembic, авторизация — PyJWT (HS256).

## Мобильное приложение

- **Раскладка.** Отсканируйте штрихкод товара и QR полки, введите количество
  и подтвердите размещение. Операция увеличит остаток на этой полке.
- **Сборка.** Откройте заказ и выберите позицию. Приложение покажет полки
  с доступным количеством. Отсканируйте товар и QR выбранной полки, затем
  подтвердите количество. Сервер спишет его с полки и обновит заказ одной транзакцией.
- **Работа без сети.** После первой загрузки данных можно продолжить работать
  в пределах действующей сессии. Приложение сохраняет очередь в SQLite и отправляет
  операции при восстановлении связи. Сервер проверяет остаток заново.
  Отклонённые операции и причина доступны на экране «Журнал».

Для Bluetooth-сканера в режиме клавиатуры поставьте курсор в поле кода.
Сканер может завершить ввод клавишей Enter. Код также можно ввести вручную.

### Локальный запуск на macOS и Linux

Для сервера нужен Python 3.12+, для мобильного клиента — Node.js 20.19+.
Выполните команды из корня проекта перед первым запуском.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Для новой установки запишите сгенерированный ключ в `JWT_SECRET_KEY` в `.env`.
Для отдельной демонстрационной базы задайте `DATABASE_URL=sqlite+aiosqlite:///./.tmp/mobile-demo.db`.

```sh
mkdir -p .tmp
python -m alembic upgrade head
python -m app.cli.seed_warehouse
python -m app.cli.create_admin --login demo_admin --full-name "Администратор склада"
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Войдите во [веб-панель](http://127.0.0.1:8000/static/login.html) под администратором,
установите пароль и подтвердите сохранение резервного кода. В разделе «Пользователи»
создайте работника и используйте его логин и временный пароль в мобильном приложении.

Запустите Expo во втором терминале.

```sh
cd mobile
npm ci
npm start
```

- **Эмулятор Android.** Нажмите `a` в Expo. Адрес API по умолчанию — `http://10.0.2.2:8000`.
- **Телефон Android.** Откройте проект в совместимой с SDK 54 версии Expo Go.
  Телефон и компьютер должны быть в одной сети. На экране входа укажите IP
  компьютера, например `http://192.168.1.10:8000`.
- **Браузер.** Добавьте `CORS_ORIGINS=http://localhost:8081,http://127.0.0.1:8081`
  в серверный `.env`, перезапустите API и запустите `npm run web` из `mobile`.
  Токены браузерной версии Expo хранятся в памяти до закрытия или перезагрузки страницы.
- **Установочный APK.** Выполните `npx eas-cli build --platform android --profile preview`
  из `mobile` после настройки проекта и учётной записи Expo. Для этой сборки используйте
  HTTPS-адрес API. [Документация Expo по APK](https://docs.expo.dev/build-reference/apk/).

Укажите адрес сервера в приложении на экране входа или в `mobile/.env` через
`EXPO_PUBLIC_API_URL`. У SQLite и PostgreSQL отдельные каталоги, заказы и аккаунты.

### Демонстрация раскладки и сборки

1. В «Раскладке» введите или отсканируйте `4601234567893` (кабель USB‑C).
   Выберите полку `A-01-01` и добавьте одну единицу.
2. Откройте заказ `ЗК-1042` и выберите кабель. В списке полок выберите `A-01-01`.
   Подтвердите тот же штрихкод и полку. Остаток на полке уменьшится на одну единицу,
   а прогресс по кабелю станет 1 из 3.
3. Для проверки офлайн отключите связь после первой синхронизации, выполните
   операцию и откройте «Журнал». Включите связь и проверьте, что операция попала
   в историю и исчезла из очереди.

Для ручного ввода используйте адрес полки, например `A-01-01`. Для печати QR
используйте поле `qr` из ответа `GET /api/v1/warehouse/snapshot`. Формат
`shelf:<id>` сохраняется при смене адреса полки. В новой демонстрационной базе
`A-01-01` соответствует `shelf:1`.

### Импорт заказов и PostgreSQL

Для импорта заказов подготовьте CSV в UTF‑8. Товары должны уже существовать
в каталоге. Один номер заказа может занимать несколько строк.

```csv
order_number,customer,product_barcode,quantity
ЗК-2001,Север Маркет,4601234567893,3
ЗК-2001,Север Маркет,4601234567909,2
```

`python -m app.cli.import_orders orders.csv` проверяет весь файл перед записью.
Существующие заказы остаются в базе. Новые номера можно импортировать из следующего файла.

Для Docker Compose укажите `JWT_SECRET_KEY` и `POSTGRES_PASSWORD` в корневом `.env`.
Для пароля БД используйте URL-безопасную строку, например результат
`secrets.token_urlsafe(24)`. Запустите `docker compose up --build`. Сервис API применит
миграции перед стартом. Создайте первого администратора и при необходимости загрузите
демонстрационные данные.

```sh
docker compose exec api python -m app.cli.create_admin --login admin_01 --full-name "Администратор склада"
docker compose exec api python -m app.cli.seed_warehouse
```

Для отдельного экземпляра PostgreSQL укажите
`DATABASE_URL=postgresql+psycopg://user:password@server/database`.

Для проверки проекта используйте `python -m pytest`, `node --test tests/*.test.cjs`
(Node.js 22.18+) и `npm --prefix mobile run typecheck`.

## Запуск в Windows

Команды выполняются из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Если `.env` уже настроен, не заменяйте существующий JWT-ключ. Для новой установки
создайте `.env` по образцу `.env.example`. Получить случайный ключ:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Сохраните результат только в `JWT_SECRET_KEY` своего `.env`. Смена ключа делает
выданные токены недействительными. Настройки:

- `ACCESS_TOKEN_EXPIRE_MINUTES=15` — access JWT;
- `SESSION_EXPIRE_HOURS=12` — абсолютное время сессии;
- `LOGIN_CONFIRM_EXPIRE_MINUTES=5` — подтверждение повторного входа;
- `PASSWORD_SETUP_EXPIRE_MINUTES=5` — запрос установки постоянного пароля;
- `AUTH_COOKIE_SECURE=False` — только для локального HTTP;
- `DATABASE_URL=sqlite+aiosqlite:///./sql_app.db` — текущая SQLite-база.

Таблицы создаются миграциями, а не при запуске приложения.
Веб-интерфейс: [страница входа](http://127.0.0.1:8000/static/login.html).
Открывайте HTML через сервер, не двойным щелчком по файлу. `/` остаётся JSON.

На складских вкладках справа от формы отображается таблица товаров, полок или
остатков (товар, штрихкод, полка, количество). Сначала видны до 5 записей;
«Показать все» загружает весь список, «Свернуть» возвращает первые 5.
После успешного действия таблица обновляется автоматически. На узком экране она
располагается под формой. GET `/api/v1/products/`, `/api/v1/shelves/` и
`/api/v1/stock/` принимают `offset` (от 0) и `limit` (1–500, по умолчанию 5).

## Первый администратор

Только на базе без администратора:

```powershell
.\.venv\Scripts\python.exe -m app.cli.create_admin --login admin_01 --full-name "Иван Петров"
```

Команда выводит временный пароль. Сохраните его безопасным способом. При наличии
администратора команда отказывает. Другие аккаунты обеих ролей создаются через
раздел «Пользователи». Публичной регистрации нет.

При первом входе пользователь устанавливает постоянный пароль. Временный пароль
не имеет срока годности и работает до успешной установки постоянного. Истечение
5-минутного setup-токена не уничтожает временный пароль: можно повторить вход.

## Восстановление доступа администратора

После обновления примените миграции и перезапустите приложение:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

При следующем входе каждый администратор должен сохранить резервный код в разделе
«Безопасность» и подтвердить сохранение. До подтверждения складские операции
недоступны. Код можно скопировать или скачать; храните его вне браузера в защищённом
месте. Действующий код не имеет срока годности и используется один раз.

На странице входа ссылка «Забыли пароль?» открывает форму: логин администратора,
резервный код, новый пароль и повтор пароля. Успешное восстановление завершает
прежние сессии. Затем нужно войти обычным способом и сохранить новый резервный код.
Работникам пароль по-прежнему сбрасывает администратор.

Если резервного кода ещё нет или потеряны и код, и пароль, владелец сервера может
выполнить из корня проекта (вход в приложение не требуется):

```powershell
.\.venv\Scripts\python.exe -m app.cli.reset_admin_password --login admin_01
```

Замените `admin_01` на нужный логин. Команда выводит временный пароль один раз,
аннулирует резервный код и завершает прежние сессии. При входе установите постоянный
пароль и настройте восстановление заново.

Подробности и новые маршруты: [docs/ADMIN_RECOVERY.md](docs/ADMIN_RECOVERY.md).

## Роли, пароли и сессии

- Администратор выполняет все складские действия, создаёт работников/администраторов
  и сбрасывает им пароли.
- Работник выполняет складские действия, кроме удаления товара и снятия товара
  с полки. Управление пользователями — только для администратора.
- На пользователя допускается одна сессия. Вход на другом устройстве требует
  подтверждения завершения предыдущей; отмена её не завершает.
- Access действует не более 15 минут. Refresh выдаёт новую пару JWT, но **не продлевает**
  12-часовую сессию. После её истечения нужен вход с паролем.
- Старый refresh одноразовый: повторное использование завершает связанную с ним
  активную сессию. Не запускайте параллельные refresh и не повторяйте их вслепую
  после сетевого сбоя. Если ответ потерян после обработки, потребуется новый вход.
- Выход, смена/сброс пароля и подтверждённый новый вход немедленно запрещают
  следующие запросы со старыми токенами соответствующей сессии.
- Своя смена пароля требует текущего пароля и завершает сессию. Сброс администратором
  генерирует временный пароль и повторяет процедуру первоначальной установки.
  При сбросе своего аккаунта сохраните выданный пароль до ухода со страницы.

Логин: 3–32 латинских буквы, цифры, `.`, `_`, `-`, без пробелов, нижний регистр.
ФИО обязательно. Новый пароль: 15–128 печатных символов, пробелы учитываются.
Требований к составу и проверки распространённых паролей нет. Новый пароль
должен отличаться от заменяемого.

## JSON API для Expo

Префикс: `/api/v1`. Защищённые запросы: `Authorization: Bearer <access_token>`.

| Метод и маршрут | Назначение / JSON |
| --- | --- |
| `POST /auth/login` | `login`, `password` |
| `POST /auth/confirm-login` | `confirmation_token`, `confirm: true` |
| `POST /auth/password/setup` | `password_setup_token`, `new_password` |
| `POST /auth/refresh` | `refresh_token`; новая пара JWT |
| `POST /auth/password/change` | Bearer + `current_password`, `new_password`; завершает сессию |
| `POST /auth/logout` | Bearer access; ответ 204 |
| `GET /auth/me` | Bearer; текущий пользователь |
| `GET /users/?offset=0&limit=100` | Список пользователей, администратор |
| `POST /users/` | `login`, `full_name`, `role`; администратор |
| `POST /users/{id}/reset-password` | Новый временный пароль; администратор |

Ответ входа определяется полем `status`:

1. `authenticated`: `access_token`, `refresh_token`, `token_type: "bearer"`,
   `expires_in` (секунды), `session_expires_at` (Unix-время), `user`.
2. `confirm_login`: `confirmation_token`, `expires_in`, `message`. Показать окно;
   подтверждать только после согласия. При отмене отбросить токен, старую сессию не трогать.
3. `password_setup`: `password_setup_token`, `expires_in`, `message`. Показать форму
   нового пароля. Этот JWT не даёт доступа к складу.

Успешные подтверждение/установка возвращают `authenticated` с парой JWT.
Типы JWT невзаимозаменяемы. Ошибки авторизации:
`{"detail": "Описание", "code": "session_ended"}`. Ошибки валидации — 422 с массивом
`detail`, без возврата введённых паролей/JWT.

Expo-клиент хранит access в памяти, а refresh в `expo-secure-store` на устройстве.
Промежуточные JWT существуют только на время шага входа.

| Метод и маршрут | Назначение / JSON |
| --- | --- |
| `GET /warehouse/snapshot` | Каталог, полки и их QR, остатки, заказы и последние 30 складских операций |
| `POST /warehouse/operations` | `operation_id` (UUID), `kind` (`putaway` или `pick`), `product_code`, `shelf_code`, `quantity`, `order_line_id` для сборки |

Повтор запроса с тем же UUID, пользователем и данными возвращает исходный результат.
При расхождении данных или недостаточном остатке сервер возвращает ошибку,
сохраняя согласованные остатки и прогресс заказа.

## Браузер

Тот же JWT-механизм, но токены находятся в HttpOnly cookies, не в JavaScript,
localStorage или sessionStorage. Браузерные маршруты:

- `GET /auth/web/csrf` — устанавливает CSRF-cookie;
- `POST /auth/web/login` — JSON `login`, `password`;
- `POST /auth/web/confirm-login` — JSON `confirm: true`;
- `POST /auth/web/password/setup` — JSON `new_password`;
- `POST /auth/web/refresh`, `/auth/web/logout`, `/auth/web/cancel-login` — без тела;
- `/auth/me` и `/auth/password/change` — общие с JSON API.

Изменяющие cookie-запросы требуют заголовок `X-CSRF-Token`, равный `inventory_csrf`
cookie. Токен подписан сервером и связан с входом/сессией. JWT cookies: `HttpOnly`,
`SameSite=Strict`, в production также `Secure`. Refresh/pending ограничены путём
`/api/v1/auth`. Встроенный клиент сам добавляет CSRF, обновляет access после 401,
отправляет формы и показывает ошибки. Web Locks синхронизирует refresh между вкладками.
Без Web Locks объединение работает только внутри вкладки: используйте одну вкладку.
Для размещения в сети нужен HTTPS. При изменении `API_V1_PREFIX` согласованно
измените префикс и адреса форм в статическом интерфейсе.

## Перед размещением в интернете

Настройте HTTPS, `AUTH_COOKIE_SECURE=True`, случайный приватный JWT-ключ и ограничение
частоты входа/setup/refresh на обратном прокси. Для восстановления и выпуска резервных
кодов уже есть собственные ограничения; они не заменяют защиту остальных auth-маршрутов.
Не включайте debug, не логируйте пароли/токены/тела auth-запросов. При необходимости
защитите Swagger. Не разрешайте CORS произвольным сайтам с credentials: встроенный
интерфейс работает с того же origin, нативный Expo-клиент не требует браузерного CORS.

Запись авторизации использует `BEGIN IMMEDIATE` в SQLite и транзакционную
блокировку в PostgreSQL. Завершённые сессии сохраняются;
периодической очистки пока нет. Блокировка аккаунтов и отдельный «выход на всех
устройствах» не добавлены, как и согласовано.

Храните `.env`, локальную `sql_app.db` и резервные копии вне Git. Чтобы подключить
существующую рабочую базу, задайте её адрес в `DATABASE_URL` и примените миграции.

Список изменений: [docs/AUTH_CHANGES.md](docs/AUTH_CHANGES.md).



После запуска доступны:

- API: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs
- Health-check: http://127.0.0.1:8000/api/v1/health
